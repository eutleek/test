1 经典布局搜索按钮外框与标签页统一

CSS 批量 46 页 行 ~5450

问题在哪

经典布局（body:not(.layout-minimal)）下，搜索按钮（.search-inline）的边框颜色没有和标签页按钮（.tab-btn）对齐。

问题文件 / 位置
index.html（及全部 46 个导航页面）
涉及 CSS 选择器
body:not(.layout-minimal) .search-inline 区域（约第 5450 行）
对照基准
.tab-btn（约第 745 行）

根因分析

标签页按钮的边框使用 var(--card-border)，悬停时变为 var(--accent)。但搜索按钮在后续的覆盖样式块中只改了圆角和图标位置，没有显式同步边框颜色，导致某些主题下两者视觉不一致。

标签页按钮的边框基准（对照标准）

/* .tab-btn 基准 - 第 745 行 */ .tab-btn { border: 1px solid var(--card-border); /* 普通 */ background: var(--card-bg); } .tab-btn:hover { border-color: var(--accent); /* 悬停 */ } .tab-btn.active { border-color: var(--accent); /* 选中 */ background: var(--accent); }

怎么修的

在 CSS 尾部（约第 5449 行）新增了一个覆盖块，强制经典布局搜索按钮的三个状态（普通/悬停/展开）都和标签页使用同一个 CSS 变量。

+/* Classic layout search fill follows tab color */
+body:not(.layout-minimal) .search-inline {
+ background: var(--card-bg) !important;
+ border-color: var(--card-border) !important;
+ backdrop-filter: blur(10px) !important;
+}
+body:not(.layout-minimal) .search-inline:hover {
+ border-color: var(--accent) !important;
+}
+body:not(.layout-minimal) .search-inline.expanded {
+ background: var(--card-bg) !important;
+ border-color: var(--card-border) !important;
+}

修复后当前代码（第 5449-5464 行）

/* Classic layout search fill follows tab color */ body:not(.layout-minimal) .search-inline { background: var(--card-bg) !important; border-color: var(--card-border) !important; backdrop-filter: blur(10px) !important; -webkit-backdrop-filter: blur(10px) !important; } body:not(.layout-minimal) .search-inline:hover { border-color: var(--accent) !important; } body:not(.layout-minimal) .search-inline.expanded { background: var(--card-bg) !important; border-color: var(--card-border) !important; }

注意事项

  • 这段覆盖使用了 !important，位于 CSS 末尾，优先级高于前面的基础定义（第 1595 行 .search-inline）
  • 杂志布局（.layout-minimal）不受此规则影响，杂志布局搜索框保持自己的透明/方角样式
  • 如果后续调整 --card-border 或 --accent 变量值，搜索框和标签页会自动同步，无需额外修改
  • 不要在这段规则之后再加不带 :not(.layout-minimal) 限定的搜索框边框覆盖，否则会影响杂志布局

2 经典布局搜索框偏白外框修正

CSS 批量 46 页 行 ~4902 / ~5466

问题在哪

经典布局下搜索框边框颜色不一致，搜索框看起来比标签页更白。有两个独立的问题来源：

问题 A — 深色主题覆盖（第 4902-4908 行）

位置
index.html 第 4902-4908 行
选择器
[data-theme="starry"] body:not(.background-image-mode) .search-inline 等

星空蓝/暮光橙/极光青主题下，有一段旧规则把搜索框强制设为白色背景和白色边框：

/* 旧代码 - 第 4902 行 - 会影响所有布局 */ [data-theme="starry"] body:not(.background-image-mode) .search-inline, [data-theme="sunset"] body:not(.background-image-mode) .search-inline, [data-theme="aurora"] body:not(.background-image-mode) .search-inline { background: rgba(255, 255, 255, 0.94) !important; /* 偏白 */ border-color: rgba(255, 255, 255, 0.88) !important; /* 偏白 */ box-shadow: 0 8px 26px rgba(0, 0, 0, 0.18) !important; }

问题 B — 图片背景模式覆盖（原第 5474 行附近）

位置
index.html 第 5474 行附近
选择器
body.background-image-mode:not(.layout-minimal) .search-inline

图片背景模式下，经典布局搜索框边框被设为 rgba(255,255,255,0.72)，比标签页更白。

怎么修的

问题 A 修复：没有删除旧规则（因为它对杂志布局仍有用），而是在后面（第 5466 行）新增了一个更具体的覆盖，用 :not(.layout-minimal) 限定只作用于经典布局：

+[data-theme="starry"] body:not(.background-image-mode):not(.layout-minimal) .search-inline,
+[data-theme="sunset"] body:not(.background-image-mode):not(.layout-minimal) .search-inline,
+[data-theme="aurora"] body:not(.background-image-mode):not(.layout-minimal) .search-inline {
+ background: var(--card-bg) !important;
+ border-color: var(--card-border) !important;
+ box-shadow: none !important;
+}

问题 B 修复：将图片背景模式下的搜索框边框从白色改为跟随 CSS 变量：

-border: 1px solid rgba(255, 255, 255, 0.72) !important;
-border-color: rgba(255, 255, 255, 0.86) !important; /* hover */
+border: 1px solid var(--card-border) !important;
+border-color: var(--accent) !important; /* hover */
+border-color: var(--card-border) !important; /* expanded */

修复后当前代码（第 5466-5488 行）

/* 深色主题经典布局搜索框 - 跟随标签页颜色 */ [data-theme="starry"] body:not(.background-image-mode):not(.layout-minimal) .search-inline, [data-theme="sunset"] body:not(.background-image-mode):not(.layout-minimal) .search-inline, [data-theme="aurora"] body:not(.background-image-mode):not(.layout-minimal) .search-inline { background: var(--card-bg) !important; border-color: var(--card-border) !important; box-shadow: none !important; } /* 图片背景模式经典布局搜索框 - 跟随标签页颜色 */ body.background-image-mode:not(.layout-minimal) .search-inline { border: 1px solid var(--card-border) !important; background: var(--card-bg) !important; box-shadow: none !important; } body.background-image-mode:not(.layout-minimal) .search-inline:hover { border-color: var(--accent) !important; background: var(--card-bg) !important; } body.background-image-mode:not(.layout-minimal) .search-inline.expanded { border-color: var(--card-border) !important; background: var(--card-bg) !important; }

注意事项

  • 第 4902 行的旧规则没有删除，它仍然作用于杂志布局（.layout-minimal），让杂志布局在深色主题下保持白色搜索框。如果删除它，杂志布局深色主题搜索框会变暗
  • 新增的覆盖在第 5466 行，因为 CSS 级联规则，后出现的同优先级规则会覆盖前面的，所以 5466 行的 :not(.layout-minimal) 版本会胜出
  • 图片背景模式下 --card-bg 在不同主题中值不同：浅色主题是 rgba(255,255,255,0.8)，深色主题是 rgba(255,255,255,0.08)，所以搜索框会自然跟随主题明暗
  • 不要把 rgba(255,255,255,0.72~0.94) 写回来，这会让搜索框在某些主题下比标签页更白

容易踩的坑

  • 如果后续批量替换脚本误删了第 4902 行的旧规则（没有 :not(.layout-minimal) 的那段），杂志布局深色主题搜索框会失去白色背景
  • 如果 CSS 顺序被打乱（比如构建工具重排序），5466 行的覆盖可能不再排在 4902 行之后，导致覆盖失效

问题在哪

根因 A — 初始 theme-color 为蓝色（第 7 行）

同时，旧代码不区分布局就直接设置主题色，杂志/极简布局下切主题也会让浏览器栏变色而非保持白色。

根因 C — querySelector 引号错误

批量脚本运行时，document.querySelector 中的引号被错误转义为 "meta[name=""theme-color""]"，导致选择器匹配失败，运行时颜色更新完全失效。

+document.querySelector('meta[name="theme-color"]')

HTML meta 标签（第 7 行）

页面内联初始化脚本（第 15-55 行）

setTheme() 运行时函数（第 7159-7183 行）

// 修复后的完整运行时逻辑 const themeColors = { "white": "#f5f5f7", "dawn": "#fff5f5", "mint": "#f0fff5", "ocean": "#f0f8ff", "twilight": "#f5f0ff", "midnight": "#000212", "starry": "#0c0c1d", "sunset": "#2d1b0e", "aurora": "#1a2a3a", "dream": "#667eea", "forest": "#2d5f4e", "deepsea": "#1a4a6e", "clay": "#6b4a35" }; const metaThemeColor = document.querySelector('meta[name="theme-color"]'); // 关键：极简布局永远白色，经典布局才跟随主题色 const currentLayout = getCurrentLayout(); if (currentLayout === "minimal") { document.documentElement.style.backgroundColor = "#ffffff"; if (metaThemeColor) metaThemeColor.setAttribute("content", "#ffffff"); } else if (themeColors[theme]) { document.documentElement.style.backgroundColor = themeColors[theme]; if (metaThemeColor) metaThemeColor.setAttribute("content", themeColors[theme]); }

注意事项

  • 初始 theme-color 必须是 #ffffff，不能改回 #0071e3，否则页面加载瞬间会出现蓝色地址栏
  • 极简/杂志布局（minimal）下浏览器栏必须始终白色，不要在 setTheme() 中把主题色赋给它
  • themeColors 映射必须包含全部 13 个主题，缺少任何一个都会导致切换到该主题时浏览器栏停留在旧颜色

  • 页面顶部内联脚本（第 15-55 行）和 setTheme() 函数（第 7151 行）中都有 themeColors 映射，两处必须保持一致

5 浏览器功能栏白边修复

CSS JS 批量 46 页

问题在哪

图片背景模式下，页面原本主要依赖 html:has(body.background-image-mode) 让 html 背景同步壁纸。部分移动浏览器对 :has()、动态地址栏区域或工具栏收起时的重绘支持不稳定，可能在顶部或底部露出白边。

怎么修的

保留原有 :has() 兜底，同时在进入图片背景模式时由 JS 给 html 添加 background-image-mode 类，并把 --bg-image 同步写到 document.documentElement。退出图片背景模式时同步移除该类，避免影响普通主题。

/* CSS fallback */ html.background-image-mode, html:has(body.background-image-mode) { background-color: #121224; background-image: var(--bg-image, none); background-size: cover; background-position: center; background-repeat: no-repeat; } // JS fallback function syncImageBackgroundChrome(bgImageValue) { document.documentElement.classList.add('background-image-mode'); document.documentElement.style.backgroundColor = '#121224'; if (bgImageValue) { document.documentElement.style.setProperty('--bg-image', bgImageValue); } }

校验结果

  • 46 个正式导航页面均已写入 html.background-image-mode CSS 兜底。
  • 旧的无参 syncImageBackgroundChrome() 和旧调用 syncImageBackgroundChrome(); 已清空。
  • 切回普通主题时会移除 document.documentElement.classList 上的 background-image-mode。

function createLinkCard(link, catIndex, linkIndex) { const cat = linksData[catIndex]; // 全球 AI 分类使用专属卡片 if (cat && cat.name === '全球 AI' && link._aiCompany) { return createAiCard(link, linkIndex); } // 其它分类仍走普通网站卡片 }

9 非壁纸主题浏览器功能栏底部白边修复

CSS 批量 46 页 .bg-gradient 层

问题在哪

使用非壁纸主题（纯色/渐变，共 13 个）时，手机浏览器底部功能栏和网页之间出现一条细白边。壁纸模式（图片背景）下没有这个问题。

问题文件 / 位置
index.html（及全部 46 个导航页面）
涉及 CSS 选择器
.bg-gradient — 非壁纸主题背景层
[data-theme="xxx"] — 主题级 html 背景色
对照基准（正常的）
.bg-layer — 壁纸模式背景层（已扩展定位，无白边）

根因分析

白边的本质是：背景层高度 = 视口高度，但视口高度在移动端是动态的。浏览器工具栏收起/展开时，100lvh 的元素不会自动跟随填补底部缝隙，导致 html 的浅色背景（#f5f5f7 白色）从缝隙里露出来。

为什么壁纸模式没事

壁纸模式的 .bg-layer 早已采用"扩展定位"方案——上下左右都向外延伸 12px，底部额外延伸 var(--safe-bottom) + 160px，所以即使工具栏变动，背景层也足够覆盖。

为什么非壁纸模式有事

.bg-gradient 原本只设置了 height: 100lvh，没有扩展到视口外。同时：

  • 浅色主题（dawn / mint / ocean / twilight）没有设置 html 级别的兜底色，html 默认是白色 #f5f5f7
  • .bg-gradient 没有 background-image，伪元素的渐变浮在上方，扩展区域没有背景填充
  • 旧方案用 body::after 伪元素做兜底层（z-index: 98），但只覆盖了暗色主题，浅色主题完全没兜住

怎么修的

核心思路：让 .bg-gradient 采用与 .bg-layer 完全相同的扩展定位模式，并补上全主题的兜底色。

修复 1：.bg-gradient 扩展定位（最核心）

-.bg-gradient {
- position: fixed;
- top: 0;
- left: 0;
- width: 100%;
- height: 100vh;
- height: 100lvh;
- z-index: -1;
- overflow: hidden;
-}
+.bg-gradient {
+ position: fixed;
+ top: -12px;
+ left: -12px;
+ right: -12px;
+ bottom: calc(-1 * (var(--safe-bottom) + 160px));
+ width: auto;
+ height: auto;
+ min-height: calc(100lvh + var(--safe-bottom) + 184px);
+ z-index: -1;
+ overflow: hidden;
+ background-image: var(--bg-primary);
+ background-size: cover;
+ background-position: center;
+ background-repeat: no-repeat;
+}

修复 2：全主题 html 兜底色（浅色主题之前漏掉了）

从"只有 8 个暗色主题有 html background-color"补全为"全部 13 个主题都有"：

-/* 暗色主题 html 背景同步 */
+/* 全主题 html 背景同步，防止移动端 overscroll / 浏览器功能栏区域白边 */
+[data-theme="dawn"] { background-color: #fff5f5; }
+[data-theme="mint"] { background-color: #f0fff5; }
+[data-theme="ocean"] { background-color: #f0f8ff; }
+[data-theme="twilight"] { background-color: #f5f0ff; }
+[data-theme="midnight"] { background-color: #000212; } /* 原有 */
+... 共 13 个主题全部补上

修复 3：.bg-gradient 主题兜底色

为所有 13 个主题的 .bg-gradient 设置匹配的 background-color，确保即使渐变图没加载或区域边缘，也有正确的纯色兜底：

/* .bg-gradient 主题兜底色，确保渐变主题在移动端底部无缝隙 */ [data-theme="white"] .bg-gradient { background-color: #f5f5f7; } [data-theme="dawn"] .bg-gradient { background-color: #fff5f5; } /* ... 共 13 个主题，颜色与 html / body 保持一致 */

修复 4：系统暗色模式 white 主题兜底

在 @media (prefers-color-scheme: dark) 块中，white 主题的 html 和 .bg-gradient 也设置 #0B1719，与 body 一致。

@media (prefers-color-scheme: dark) { [data-theme="white"] body { background-color: #0B1719; } [data-theme="white"] { background-color: #0B1719; } [data-theme="white"] .bg-gradient { background-color: #0B1719; } }

修复 5：移除 body::after hack

删除了移动端 body::after 伪元素兜底层（z-index: 98，底部 10px 高），因为现在 .bg-gradient 扩展定位已经覆盖了整个区域，不需要额外的兜底层了。同时删除了 8 个暗色主题的 body::after 颜色覆盖。

修复 6：手机端 .bg-gradient 扩展覆盖

把 .bg-gradient 加入到手机端 .bg-layer / .bg-layer-fade 的扩展覆盖规则中，使用更大的延伸量（底部延伸 220px）：

@media (max-width: 768px) { .bg-gradient, .bg-layer, .bg-layer-fade { bottom: calc(-1 * (var(--safe-bottom) + 220px)) !important; min-height: calc(100lvh + var(--safe-bottom) + 244px) !important; } }

修复原理总结（三层兜底）

  • 第一层：.bg-gradient 扩展定位 + background-image，实际渐变/纯色覆盖到视口外 160px+
  • 第二层：.bg-gradient 的 background-color 兜底，即使渐变没铺满也有正确颜色
  • 第三层：html 级别的 background-color，极端情况下（如 overscroll）也不会露白

校验结果

  • 46 个正式导航页面均已应用修复。
  • CSS 大括号匹配全部通过（index.html: 1863/1863，acgn.html: 1677/1677 等）。
  • body::after hack 已从所有正式页面移除，仅备份文件中残留。
  • 13 个主题的 html 和 .bg-gradient 均设置了匹配的 background-color。

注意事项 / 维护须知

  • .bg-gradient 和 .bg-layer 应该保持相同的定位扩展模式，不要一个用 100lvh 一个用负偏移
  • 新增主题时，必须同时在三个地方加背景色：body、html（[data-theme="xxx"]）、.bg-gradient（[data-theme="xxx"] .bg-gradient）
  • 系统暗色模式（prefers-color-scheme: dark）下 white 主题的三处兜底色（body / html / .bg-gradient）必须都设为 #0B1719
  • 不要把 body::after 兜底层加回来，它会引入 z-index 层级问题，而且现在已经不需要了
  • 手机端媒体查询里 .bg-gradient, .bg-layer, .bg-layer-fade 三个选择器要放在一起，共享同一套扩展值

  • 有一次 PowerShell 脚本的正则匹配范围过大，意外替换掉了部分 CSS/JS 内容（5 个文件被截断）。通过从 index.html 回填完整 CSS 区块恢复

14 杂志布局刷新/跳转时经典布局闪烁修复

CSS JS 46 页同步 FOUC 修复

问题描述

使用杂志布局（minimal）时，每次刷新页面或跳转到子页面，都会先闪出一次经典布局（grid），然后才切换到杂志布局。用户体验不佳，尤其是在快速导航时闪烁明显。

根因分析

  • 布局类 layout-minimal / layout-grid 是通过页面底部的 setLayout() 函数添加到 <body> 上的
  • setLayout() 在 DOMContentLoaded 后才执行，此时浏览器已经开始渲染页面
  • body 默认没有布局类，CSS 规则中的 body.layout-minimal 选择器不匹配，页面先以默认（经典布局）样式渲染
  • 等 JS 执行完加上类名后，页面才跳转到杂志布局 — 产生 FOUC（Flash of Unstyled Content）

解决方案

在 <body> 标签之后立即插入一段内联脚本，在页面内容渲染之前就读取 localStorage 并给 body 加上布局类：

<body> <script> // Pre-set layout class to prevent flash of classic layout on page load (function() { var saved = localStorage.getItem('layout') || 'minimal'; document.body.classList.add('layout-' + saved); })(); </script> <div class="bg-layer"></div>

这样浏览器在解析 body 内容的第一时间就有了正确的布局类，所有 CSS 规则（body.layout-minimal）从一开始就生效，不会再有经典布局的闪烁。

与 setLayout 的兼容性

  • setLayout() 函数执行时会先 remove('layout-grid', 'layout-minimal') 再添加正确的类，不会与预设类冲突
  • 内联脚本使用 var 和 IIFE，不会污染全局作用域
  • 默认值 'minimal' 与 initColors() 中的默认布局一致

46 个 HTML 文件（index.html + 45 个子页面）。disclaimer.html 无布局切换，不涉及。

  • 第 7159 行 — setTheme() 函数中的映射

  • PowerShell 脚本中尽量不要在正则匹配模式里使用中文字符，可能因编码问题导致解析失败
